# F02 — Browse events and inspect details

Target specification. Inherits [shared flow contract](../USER_FLOWS.md#shared-flow-contract-and-state-vocabulary),
[UI/recovery requirements](../UI_UX.md#shared-ui-state-and-recovery-contract) and
[evidence matrix](../USER_FLOWS.md#evidence-matrix-for-each-delivered-flow).
[Flow index](../USER_FLOWS.md) · [Delivery gates](../../DEVELOPMENT_PLAN.md).


- **Actor / prerequisites:** public visitor or any authenticated user. Public
  discovery is proposed under UX-D02; current event data requires authentication.
- **Entry / screens:** S01 home/event list; direct S02 link.
- **Happy path:** choose language → browse permitted current/upcoming/past summaries
  → open event → inspect dates/stage/venue/requirements → apply, resume, open an
  authorized workspace or view published results when those actions are delivered.
- **Validation / permissions:** public/private DTO boundary explicit; no private
  application/roster data in discovery. Backend determines stage availability.
  New non-admin applications only PRE_REGISTRATION/REGISTRATION_OPEN today.
- **Alternate / failure:** unauthenticated current API access explains sign-in with
  return; unavailable/private ID follows privacy-safe not-found behavior; canceled
  event explains status; closed applications offer permitted status/contact path.
- **Loading / empty:** summary/detail skeleton; no events differs from failed fetch
  or no filter matches; non-admin empty state never offers admin-only creation.
- **Cancel / recovery:** return to prior list/filter/scroll; retry reads safely;
  recheck stage on starting application after a long-open detail page.
- **Result / stages:** viewing makes no mutation; all existing stages readable
  when authorized. Current/upcoming/past by dates differs from lifecycle stage.
- **Dependencies:** event clients/DTOs; owned registration reads for resume;
  UX-D02/public DTO before public data, P3-REGISTRATION for deadlines/timezone.
- **Acceptance:** every visible action resolves; DATA_REVIEW does not invite a new
  application; guest/sign-in/retry/empty behavior is explicit; long localized dates
  remain readable on phone without revealing protected data.
