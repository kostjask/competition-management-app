# F12 — Edit, preview and publish studio/festival content

Target flow, not an implemented CMS. [Scope](../PRODUCT_SCOPE.md) ·
[S20](../ui/public.md#s20--shared-content-administration) ·
[Website tasks](../roadmap/website.md) · [Shared recovery](../USER_FLOWS.md)

- **Actor / prerequisites:** controlled, active eligible developer/director
  administrator. No public admin signup or privilege from teacher/judge/contact
  presentation. Existing festival assignments alone grant no content editing.
- **Entry:** authenticated workspace → Studio website or selected festival edition.
- **Happy path:** edit draft ET/EN/RU content/media/branding → save acknowledged
  revision → authorized preview → resolve readiness/translation/link issues →
  explicitly publish the reviewed revision → verify anonymous output. Unpublish
  is a separate explicit operation with affected links/assets explained.
- **Edition copy:** copy selected presentation to a new draft; review dates/rules;
  never copy participants, approvals, scores or published results automatically.
- **Boundaries:** ordinary draft edits leave published content unchanged. Preview
  requires authorization and stays out of indexing/public caches. Public asset
  retrieval follows live published references; replacement/unpublish cache and
  retention behavior must be decided in P4-PUBLIC-MODEL before implementation.
  CMS actions do not alter event stages, rule freezes, applications or score locks.
- **Failure / recovery:** field-linked validation, retained local work, stale
  revision comparison and explicit retry/reconciliation after uncertain response;
  session recovery never blindly republishes. Backend denies ordinary users,
  unrelated staff and inaccessible targets. A public release failure cannot
  produce a false published acknowledgement.
- **Acceptance:** two administrators can edit concurrently without lost updates;
  publication/audit is atomic according to the chosen model; published revision
  and anonymous output agree; rollback/unpublish and media references are tested.
  Include ET/EN/RU, keyboard/assistive/responsive and rendered visual review.
  Source/API names and readiness policy remain P4-PUBLIC-MODEL decisions.
