# F01 — Account registration, verification, login, logout and recovery

Target specification. Inherits [shared flow contract](../USER_FLOWS.md#shared-flow-contract-and-state-vocabulary),
[UI/recovery requirements](../UI_UX.md#shared-ui-state-and-recovery-contract) and
[evidence matrix](../USER_FLOWS.md#evidence-matrix-for-each-delivered-flow).
[Flow index](../USER_FLOWS.md) · [Delivery gates](../../DEVELOPMENT_PLAN.md).


- **Actor / prerequisites:** new studio applicant with valid server onboarding
  context (target), existing account holder or invited user; P2 eligibility,
  token/session/retention decisions and real email before external use. No spectator signup.
- **Entry / screens:** S03 from home/event application; S04/account menu; verified
  safe email links. Existing users can sign in without creating another account.
- **Happy path:** retain event/language → establish studio onboarding intent on
  server → collect name/email/password → acknowledge account creation without
  claiming a session → check-email screen → consume valid verification link →
  explicit Continue to permitted saved destination. Login validates account and
  returns there; absent destination opens application/workspace selection.
  Logout resolves unsaved-work prompt, clears session/private view, returns to
  sign-in. Recovery requests email under enumeration-safe policy, validates a
  purpose-bound token, sets new password, then follows agreed session policy.
- **Validation / permissions:** shared credential schemas plus backend eligibility,
  active/verified account checks, safe internal redirect validation, rate limiting,
  expiry/single consumption. Public payload cannot choose role/event privileges.
  Current login still admits unverified active users; enforcement is not complete.
- **Alternate / failure:** duplicate account → sign-in/recover; mistyped email →
  agreed correction path; delivery failure → truthful status/retry; expired/used
  verification → safe resend or sign-in, never default to registering again.
  Signed-in link shows intended identity; wrong account switches safely. Invalid
  credentials and throttling use localized safe errors. Offline never implies sent.
- **Loading / empty:** session bootstrap has a labeled wait; no onboarding context
  offers studio start/event selection; missing token explains recovery action.
- **Cancel / recovery:** leave only after resolving unsaved form; never persist
  password. Session expiry recovers approved server progress and rechecks authority;
  cross-device link uses defined fallback, not stale in-memory router state.
- **Result / stages:** unverified account → verified eligible account → authorized
  session; logout has no studio/event/entry deletion. Account work is independent
  of event stage; resuming a closed application explains the new stage restriction.
- **Dependencies:** current `/auth/register`, `/auth/login`, `/auth/verify-email`,
  `/auth/profile`; reset/resend/context and session invalidation policy pending
  P2-AUTH/SESSION/SIGNUP/IDENTITY-TOKENS/EMAIL and I18N-PREFERENCES.
- **Acceptance:** all three languages; keyboard/password manager works; no
  signup bypass or staff selection; no false sent/login; expired/wrong-purpose/
  replay links fail safely; event return and inactive/wrong-account cases tested.
