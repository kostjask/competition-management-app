# F07 — Entry data review and performance scheduling

Target specification. Inherits [shared flow contract](../USER_FLOWS.md#shared-flow-contract-and-state-vocabulary),
[UI/recovery requirements](../UI_UX.md#shared-ui-state-and-recovery-contract) and
[evidence matrix](../USER_FLOWS.md#evidence-matrix-for-each-delivered-flow).
[Flow index](../USER_FLOWS.md) · [Delivery gates](../../DEVELOPMENT_PLAN.md).


- **Actor / prerequisites:** approved representative reviews own data; admin
  reviews submitted entries; authorized scheduler after live model. M2 does not
  depend on scheduling. Entry review uses P3-ENTRIES/HISTORY, scheduling P6 models.
- **Entry / screens:** S12 review and field-linked editors; S13 schedule editor.
- **Happy path:** refresh authoritative entry/music validation → resolve blocking
  issues → distinguish optional warnings → F10 submission/receipt → admin checks
  completeness/corrections → scheduler selects stage/session and entries →
  generates/previews order → resolves dancer/timing conflicts → saves validated revision.
- **Validation / permissions:** submission checks age/count/duration/music and
  ownership server-side; scheduling only agreed submitted/eligible entries,
  event-consistent stage/session, unique slots and participant timing rules.
  Do not require a schedule slot to save or submit a draft entry.
- **Alternate / failure:** missing music/configuration → precise entry link;
  withdrawn/disqualified entry follows agreed policy; generation conflict shows
  affected performances; stale revision rejects overwrite; live schedule edits
  require authorized exception rules and audit.
- **Loading / empty:** validation/generation progress; no entries versus no
  eligible unscheduled entries; failed review never says all clear.
- **Cancel / recovery:** cancel preview keeps current schedule; explicit move
  controls supplement drag; uncertain save reads current revision; corrections
  preserve unaffected entries and return to the same checklist/filter.
- **Result / stages:** validated entries/submission state separate from scheduled
  stage/session slots; current orderOnStage alone is insufficient. DATA_REVIEW
  corrections require explicit allowance; SCHEDULED/LIVE semantics await ADR-003.
- **Dependencies:** current scoped entry/config reads; validation/submit/receipt,
  revision/correction and schedule commands pending P3/P5/P6 contracts.
- **Acceptance:** checklist links reach exact field; schedule reorder atomic and
  repeat-safe; keyboard/touch alternative works; dancer conflicts/stale changes
  surfaced; review success is based on the same revision later submitted/scheduled.
