# F09 — Judge scoring, autosave, submit, lock and correction

Target specification. Inherits [shared flow contract](../USER_FLOWS.md#shared-flow-contract-and-state-vocabulary),
[UI/recovery requirements](../UI_UX.md#shared-ui-state-and-recovery-contract) and
[evidence matrix](../USER_FLOWS.md#evidence-matrix-for-each-delivered-flow).
[Flow index](../USER_FLOWS.md) · [Delivery gates](../../DEVELOPMENT_PLAN.md).


- **Actor / prerequisites:** active assigned event judge with matching role/Judge,
  versioned rubric, current performance and exact score/recovery policy.
- **Entry / screens:** S15 after F06 or returning judge landing.
- **Happy path:** load correct performance/rubric/own sheet → enter valid criterion
  values → mark unsaved → autosave draft → show saved only after server revision
  acknowledgement → review complete sheet → explicit final submit → show server
  receipt/lock → wait or open next assigned performance according to queue policy.
  Authorized correction reopens a defined sheet/scope, records reason, then
  resubmits a new version without erasing the earlier acknowledged record.
- **Validation / permissions:** assigned judge/performance/event/criterion identity;
  finite exact values within range/step, required criteria and allowed comments;
  missing differs from zero. Locks enforced backend; peer-score visibility follows
  ADR-004; stage/session UI cannot silently reassign a pending score sheet.
- **Alternate / failure:** invalid value stays visible with field error, never
  clamped silently; failed draft says unsaved; lost submission response reads own
  server sheet before retry; stale version supports compare/reapply under policy.
  Permission removal/session expiry blocks writes without claiming submission.
- **Loading / empty:** rubric skeleton; no assignment/waiting explains next action;
  failed fetch is not an empty score sheet; locked read view shows submitted time/version.
- **Cancel / recovery:** leaving pending edits warns; cancel final confirmation
  retains draft. Offline durable queue is undecided; display actual local/server
  distinction and block unsupported submission. Reconnect checks sheet/queue/version
  before allowing replay or advancing. Never put private drafts into ad-hoc storage.
- **Result / stages:** target unsaved → saving → acknowledged draft → submitted →
  locked; correction is authorized audited revision. These are sheet states,
  separate from lifecycle; LIVE/SCHEDULED mapping awaits ADR-003/004.
- **Dependencies:** P6-SCORING-MODEL/TEMPLATES/JUDGE/RECOVERY, P4-STAFF; no current
  mounted scoring endpoint establishes these guarantees. Debounce/transport and
  duplicate-operation keys require an explicit backend/client contract.
- **Acceptance:** draft acknowledgement survives reload; lost response/repeated
  submit creates one accepted version; locked/foreign/unassigned writes fail;
  decimal locales, zero/missing, reconnect during edit and authorized correction
  tested; no peer leak or unexpected focus/performance switch.
