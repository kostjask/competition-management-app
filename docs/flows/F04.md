# F04 — Manage representatives, dancers, performances and music

Target specification. Inherits [shared flow contract](../USER_FLOWS.md#shared-flow-contract-and-state-vocabulary),
[UI/recovery requirements](../UI_UX.md#shared-ui-state-and-recovery-contract) and
[evidence matrix](../USER_FLOWS.md#evidence-matrix-for-each-delivered-flow).
[Flow index](../USER_FLOWS.md) · [Delivery gates](../../DEVELOPMENT_PLAN.md).


- **Actor / prerequisites:** own active studio member with event permissions,
  organization approval and APPROVED event registration for entry operations;
  admins retain operation-specific bypass, never parent/active-record bypass.
- **Entry / screens:** S07 → S08 profile, S09 roster, S10 entry, S11 music;
  additional representatives through S17 and F06 after studio invitation policy.
- **Happy path:** select authorized event/studio → inspect locks → update permitted
  profile or own contact → add/edit roster with calendar birth dates → create
  unscheduled draft entry (target) → select participants/options and duration →
  save acknowledged revision → upload valid music → preview → proceed to F07/F10.
  Authorized member inviter selects exact studio/email, sends scoped invitation;
  intended account accepts, membership is verified, and removal preserves history.
- **Validation / permissions:** changing contact email never changes account login
  identity. Additional-member invitation cannot be replaced with contact editing.
  Entry backend checks every participant's active same-studio relationship,
  configuration event, age date, count, duration and deadlines under agreed policy.
  Current setup reads require event.manage: add safe representative option DTOs
  before building selectors, rather than widening administrative permissions.
- **Alternate / failure:** invalid birth date/eligibility/count → exact field issue;
  unavailable option → refresh while preserving selections; archived participant
  cannot remain in PATCH; stale revision → compare/reapply. Music type/size/duration
  rejection, interruption or processing failure retains old working file.
- **Loading / empty:** scoped list skeletons; no dancers invites authorized add;
  no options explains organizer setup blocker; no performances/music has distinct
  add/upload actions; locked status is never an empty list.
- **Cancel / recovery:** cancel editor retains saved version; unsaved warning before
  leaving. Confirm archive and explain retained history/no current restore. Upload
  cancel does not detach prior file; uncertain save reconciles revision first.
- **Result / stages:** current CRUD persists complete records; durable partial
  drafts and media state are pending. Profile writes for non-admins in
  PRE_REGISTRATION/REGISTRATION_OPEN; roster/entry writes REGISTRATION_OPEN or
  DATA_REVIEW with explicit review override. Reads have their separate approval gates.
- **Dependencies:** studio/member/dancer/performance clients, P3 ownership/history/
  drafts/calendar/media decisions, P4-ENTRY-CONFIG, P5-ENTRIES/MEMBERS/MUSIC,
  P8-MEDIA. Current required orderOnStage is not the target draft experience.
- **Acceptance:** all relationships checked on server; stage change preserves
  visible input without false save; draft survives return only after storage is
  implemented; failed replacement retains playable old file; unauthorized member
  invite/removal and cross-event/studio attempts fail without partial changes.
