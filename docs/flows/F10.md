# F10 — Final entry submission and results finalization/publication

Target specification. Inherits [shared flow contract](../USER_FLOWS.md#shared-flow-contract-and-state-vocabulary),
[UI/recovery requirements](../UI_UX.md#shared-ui-state-and-recovery-contract) and
[evidence matrix](../USER_FLOWS.md#evidence-matrix-for-each-delivered-flow).
[Flow index](../USER_FLOWS.md) · [Delivery gates](../../DEVELOPMENT_PLAN.md).


Entry submission and official result publication are separate operations below;
their receipts, authority and locks must never share a misleading “finalized” badge.

- **Actor / prerequisites:** approved representative with latest validated own
  entries for entry submit; authorized admin with complete accepted sheets and
  versioned scoring rules for results; public viewer only after publication policy.
- **Entry / screens:** S12 entry review/receipt; S16 private results/public results.
- **Happy path (entries):** complete F07 checks → confirm lock consequences and
  selected revision → server validates/commits once → show receipt with event,
  studio, summary, time/version and next step. Correction requests define affected
  scope, reason and deadline; permitted edits create a new audited submission.
- **Happy path (results):** calculate from accepted sheet/rule versions → inspect
  missing data/ties/penalties/group totals → resolve blockers → confirm finalization
  → preview public-safe output → confirm publication of specific revision → show
  publication time/version → public users filter groups/view permitted exports.
- **Validation / permissions:** final server checks, idempotent commands and stale
  revision detection; only authorized admin may finalize/publish; unpublished
  data never appears in public HTML/DTO/export. Enforce exact rounding/tie rules;
  do not treat event FINALIZED as automatic public publication.
- **Alternate / failure:** missing sheet/invalid calculation blocks finalization;
  concurrent correction invalidates stale preview; failed export is retryable read;
  notification failure does not undo committed submit/publication. Corrections
  after publication need reason/new version/time and visible correction notice.
- **Loading / empty:** validation/calculation progress; no entries, no accepted
  sheets and no published results have distinct next actions; private review
  failure never renders zero scores or a false complete result.
- **Cancel / recovery:** cancel confirmation leaves submitted/public state unchanged;
  lost acknowledgement reconciles receipt/publication version before retry;
  withdrawal/unpublish/rollback available only after explicit authority/policy,
  never silent destructive undo of official history.
- **Result / stages:** entry receipt/locked revision; separate provisional →
  finalized → published → corrected results under ADR-004. Lifecycle compatibility
  with FINALIZED/ENDED/CANCELLED awaits agreed mapping; public viewing is read-only.
- **Dependencies:** P3-ENTRIES/HISTORY, P5-SUBMISSION; P6-SCORING-MODEL, P7-CALCULATE/
  PUBLISH/EXPORT and ADR-002 public DTO decision. No current final-submit or results
  API is claimed. CSV/PDF exports follow privacy and ET/EN/RU policy.
- **Acceptance:** reproducible golden calculation fixtures; no duplicate receipts/
  publications; stale or unauthorized commands fail without partial changes;
  corrections retain old versions; direct public URLs/export requests cannot
  expose provisional/private data; tables and ties understandable with screen reader.
